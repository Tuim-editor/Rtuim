# TUIM bug-report gateway

This Cloudflare Worker receives the in-app report and creates an issue through
a GitHub App. GitHub credentials remain in encrypted Worker secrets; TUIM and
its users never receive or handle them.

## Payload contract

Send `POST /report` with `Content-Type: application/json` and this payload:

```json
{
  "category": "Editor",
  "summary": "Cursor jumps when opening a file",
  "description": "Optional details and reproduction steps",
  "diagnostics": "{\"os\":\"linux\",\"architecture\":\"x86_64\"}"
}
```

- `category`: exactly `Editor`, `Terminal`, `Git`, `Extensions`, `Performance`, or `Other`.
- `summary`: a nonblank string, at most 120 Unicode characters (code points,
  matching Rust's `chars().count()`, not UTF-16 units). Surrounding whitespace
  counts toward the limit and is trimmed in the issue title.
- `description`: an optional string, at most 6,000 Unicode characters. Omitted
  and empty descriptions are accepted; `null` is not a string.
- `diagnostics`: a required string, at most 40,000 Unicode characters. It may
  contain serialized JSON but is treated as text, not a nested object. Empty
  strings are accepted. The gateway uses a fenced code block, prefixing any
  potential closing-fence lines with a zero-width space so diagnostics cannot
  close the block or inject rendered Markdown/HTML. Rendering overhead stays
  bounded even for adversarial delimiter runs.

The client redacts before upload and bounds the redacted fields. Redaction can
expand text; the gateway still enforces the limits above. The request body is
limited to 560,000 UTF-8 bytes, allowing all fields at their limits even when
astral characters use JSON-escaped surrogate pairs. The former `metadata`/`logs`
payload is not supported.

Success is HTTP `201` with
`{"issueUrl":"https://github.com/OWNER/REPO/issues/42","issueNumber":42}`.
Errors return JSON containing `error`: `400` for malformed JSON, `405` for an
unsupported method, `413` for excessive request bytes, `415` for a non-JSON
content type, `422` for invalid fields, `429` for the gateway's rate limit, and
`502` for a GitHub authentication, transport, or issue-creation failure
(including GitHub's own rate limits). `GET` returns a service readiness response,
not a live GitHub credential check. No user login, GitHub token, or authorization
header is required from TUIM users.

## One-time maintainer setup

1. Create a GitHub App owned by the repository owner.
2. Give it **Issues: Read and write** and **Metadata: Read-only** repository
   permissions. It needs no user permissions or webhook.
3. Install it only on `Tuim-editor/Rtuim` and record the App and installation IDs.
4. Generate and download a private key. Keep it outside this repository.

GitHub installation tokens are short-lived and are generated by the Worker for
the single configured repository.

```sh
cd reporting
cp wrangler.example.toml wrangler.toml
npm ci
npm run typecheck
npm test
npx wrangler login
npx wrangler kv namespace create REPORT_LIMITS
```

Put the returned namespace ID in the ignored local `wrangler.toml`, then configure secrets. Run
these commands yourself; do not paste their values into source files or chat:

```sh
npx wrangler secret put GH_APP_ID
npx wrangler secret put GH_INSTALLATION_ID
npx wrangler secret put GH_PRIVATE_KEY
npm run deploy
```

Only a maintainer should provision secrets or deploy. Local verification below
does not need Cloudflare credentials or a deployment, and sends no live reports.

Configure the Rust client's **compile-time** `TUIM_BUG_REPORT_URL` with the
resulting HTTPS URL, including `/report`. For a local build, from the repository
root:

```sh
TUIM_BUG_REPORT_URL=https://rtuim-bug-report.YOUR_SUBDOMAIN.workers.dev/report cargo build --release
```

For release builds, set the repository Actions **variable** `TUIM_BUG_REPORT_URL`
(Settings > Secrets and variables > Actions > Variables) to that same public
endpoint. The release workflow passes it into the Rust build; rebuild/release
after changing it. Releases fail early if this variable is missing or not HTTPS.
This URL is not a secret and must never contain GitHub credentials. A runtime
`TUIM_BUG_REPORT_URL` override is also supported for testing or self-hosting, but
normal users should never need it. Without either setting, development builds
retain the historical `https://tuim-bug-report.workers.dev/report` fallback; its
availability is not guaranteed. Verify your deployed service before releasing.

## Local verification

Use Node.js 22 or newer and the locked development dependencies:

```sh
cd reporting
npm ci
npm run typecheck
npm test
```

Tests compile the actual TypeScript Worker into a temporary directory, use Node's
built-in test runner, generate a temporary RSA key locally, and intercept every
GitHub fetch. No additional test framework, user authentication, real GitHub
credentials, deployment, or live report is needed. Tests cover all categories,
optional descriptions, invalid payloads, Unicode and byte bounds, safe diagnostics
rendering, GitHub App signing/token caching, upstream failures, and rate limiting.

## Abuse and privacy controls

- Reports are limited to five attempts per source IP per UTC hour using Workers
  KV and SHA-256-hashed IP keys with a two-hour TTL. Missing source IPs share an
  `unknown` bucket. KV's eventually consistent read/increment is best-effort,
  not a strict concurrent/distributed quota. Failed/invalid attempts after the
  initial method, media-type, and declared-size checks also consume the budget.
- Input fields and request size are strictly bounded.
- The Rust payload contains category, summary, description, and runtime diagnostics.
  It does not attach the former Zig client’s log excerpt.
- Runtime diagnostics include Tuim version, OS, architecture, mode, theme,
  terminal dimensions/capabilities and emitted bytes.
- The client attempts home-path and token redaction. Review reports before
  sending; redaction cannot guarantee that every secret is detected. Transport
  tests use local mocks; live delivery has not been exercised by these tests.
- The gateway does not log report bodies or source IPs.
